# Alfred 0.1.0-beta.4

Reduces desktop memory overhead, especially before opening the quick overlay and
after dismissing it.

- Creates the overlay only when opened, avoiding a second WebView2 renderer at startup.
- Releases the overlay renderer when explicitly dismissed with Escape or its close button.
- Keeps the conversation when toggling the overlay with Alt+Space or the tray menu.
- Stops hidden overlay voice capture and resumes voice mode when summoned again.
- Loads only the interface needed by each window: workspace, overlay, or Android assistant.
- Requests lower WebView2 memory use while windows are hidden or minimized, while
  keeping reminder timers running.
- Cleans up overlay event listeners, pending requests and queued prompts.

An isolated Windows development startup comparison reduced private committed
memory from about 255 MiB to 194 MiB (24%) and renderer count from two to one.
This is a single controlled measurement, not a guaranteed reduction for every
device or existing session. Task Manager's default Memory column uses a different metric.

## Update

Open **Settings → App updates → Check for updates**, then choose **Download and
install**. Save your work first. Alfred verifies the signed update and restarts.
Beta.1 users must install the Windows x64 `.exe` manually once.

The installer uses the existing updater signing key. Windows publisher signing
remains unconfigured, so Windows may show a publisher or reputation warning.

## Validation

Development-mode frontend regression, startup/authentication and overlay lifecycle
checks passed with stubbed responses and capture. Native isolated-profile checks
confirmed on-demand overlay creation, dismissal, recreation, and window
minimize/restore. No personal app data was used or changed. Real microphone/AI
use, a live beta.3-to-beta.4 install/update, and long-duration memory profiling
have not been performed for this release.

Release checks passed: 48 frontend tests, 86 backend tests with isolated databases
and stub providers, three native updater tests, full ESLint, TypeScript, startup,
overlay, reliability/update UI checks, and the development frontend build.
