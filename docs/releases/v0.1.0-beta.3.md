# Alfred 0.1.0-beta.3

Fixes the welcome screen being skipped before choosing guest access or Google.

- The hidden Windows overlay no longer creates a guest account at startup.
- The welcome screen waits for **Continue as guest** or a successful Google
  sign-in before opening the workspace and starting the tour.
- The overlay and schedule notifications wait for the same account choice.
- Background API requests cannot silently create a guest account.
- Existing guest sessions may ask for confirmation once after this update.
  **Continue as guest** reuses the existing account and preserves its content.
  Later launches remember that choice.
- Google sign-in errors keep the welcome screen available instead of starting
  the tour with the temporary guest used for sign-in.

## Update from beta.2

Open **Settings → App updates → Check for updates**, then choose **Download and
install**. Save your work first. Alfred verifies the signed update and restarts
after installation.

Beta.1 has no updater; install this version's Windows x64 `.exe` manually once.
Windows publisher signing remains unconfigured, so Windows may show a publisher
or reputation warning.

## Validation

Development-mode regression coverage mounts the main window and overlay together
and checks first launch, explicit guest choice, remembered choice, preserving
existing guest data, and Google sign-in failure/success ordering. Automatic tests
use stub responses and temporary browser storage. The installer is signed with
the same updater key as beta.2; live install/restart verification is left to the
requested beta.2-to-beta.3 update test.
